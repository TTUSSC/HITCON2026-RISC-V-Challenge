# 好關卡設計原則

本文件整理自 2026-08-21 針對 L0/L1/L2 三個分支所做的認知負擔專項審查
（`cogload-review-L0.md` / `-L1.md` / `-L2.md`，由 codex 以三個分支各自的
目標受眾角度分析）。三份文件各自獨立發現同一組根因，代表這些不是單一分支
的個案問題，而是這個平台目前系統性缺少的設計元素。

本文件把那些發現轉成**正面的設計原則**——之後新關卡、review 既有關卡，
或是修正被抓到的關卡，都應該用這份清單當作「好長怎樣」的參照，而不是每次
重新發明。

---

## 1. 好的關卡結構（Level Structure）

**目標步數：5-10 步一關**（Duolingo 的實際節奏），不是「能塞進 2-3
步就是精簡」。目前 L0/L1/L2 幾乎每一關都卡在 1-3 步，這是三份 review 一致
指出的根本問題，不是內容太少，是把好幾個概念硬塞進同一畫面。

**每一步只加一個新東西**——一個新概念、一個新狀態改變、或一次新的組合，
不是同時三四個。判斷標準：這一步拿掉之後，學習者少學到的東西能不能用一句
話講完？講不完就代表塞太多。

**Worked example 一定要在 practice 之前**，不能反過來，也不能省略。順序
固定是：

```
觀察／示範（沒有評分）→ 練習（單一新概念，evaluated）→ 可見結果回饋
```

一個關卡如果只有「唸一段文字 → 直接考」兩步，中間永遠缺了讓學習者先看過
一次「正確長什麼樣子」的步驟。

**分支/子關卡串起來要有遞增的中間推理，不能整套鷹架一次拆光。** L2-Bonus
被抓到的問題正是「前面每一步都有提示，最後一步突然全部拿掉」——鷹架要
逐步撤除，不是一次全撤。多子關卡的敘事（例如 L2-5a/b/c 找 offset → 找
target → 組 payload）要確保每一段自己就有可推導的中間依據，不能要求學習者
單靠記憶前一段講過的數字。

**每個分支要有至少一次「合併檢查點」**——單獨教過的東西，要有一步要求
學習者同時用上兩個以上已學概念（例如 L1 從頭到尾沒有任何一步要求同時填
a0 又填 a7）。合併檢查點是確認「學習者真的內化了，不是背了單一事實」的
唯一辦法。

## 2. 好的教學敘述（Teaching Narrative）

**用歸納，不要用宣告。** 目前的通病是「a0 是第一個參數」直接當事實講出來，
學習者只能死記。更好的做法：先給 2-3 個具體例子（例如不同函式呼叫，參數
落在不同位置），讓學習者自己觀察規律、回答「這個位置的參數在哪個暫存器」，
最後才把規則講白當作確認，而不是最初就講白。

**縮寫/僞指令要教「為什麼」，不是只給展開式。** `li`/`mv`/`ret` 這類
pseudo-instruction，光講「這是 XXX 的縮寫」學習者只能硬背對照表。應該讓
學習者看到兩種寫法產生完全相同的暫存器前後狀態，用視覺證明「這兩行對
emulator 來說沒有差別」，讓「為什麼可以這樣縮寫」變成看得到的事實，不是
背出來的規則。

**跳躍類指令即使不列入考核，也該有描述性的鋪陳。** L0 目前直接預覽 `ret`
卻從沒解釋過「跳躍」是什麼，等於預告一個沒有定義過的詞。裸的詞彙表
（beq/bne/blt/bge 一次全上）也是同樣的問題——沒有先建立「條件可以選擇
下一行執行到哪裡」這個基礎模型，就直接丟四種比較符號進來。

**先建立好的抽象，再命名它。** 錯誤順序是「先講名詞，再讓學習者事後拼湊
意思」；正確順序是「先讓學習者看到現象（例如一個值從記憶體被搬進暫存器），
再告訴他這叫 load」。

**內容範圍要守住，不要提前洩漏還沒教的概念。** L0-4 混進了「syscall」、
「編譯成 vulnerable binary」這類 L1/L2 才會出現的詞，對正在建立分支模型的
學習者只會增加無關的認知負擔，不會幫助理解當下的主題。

**「記憶體」這個概念要儘早、獨立地建立，不能假設學習者已經知道地址是
什麼。** 三份 review 都指出同一件事：地址（`la a1, msg`、buffer 位置、
stack offset）從 L2-1 開始就直接被使用，但記憶體本身作為一個概念從未被
畫出來過——`StackDiagram` 第一次出現已經是 L2-5a，太晚了。任何要求學習者
操作地址的關卡，都必須先有一步讓學習者「看到」記憶體長什麼樣子，地址是
指向哪裡。

## 3. 好的 UI 設計（UI Design）

**核心原則：emulator 已經算出來的真實狀態，必須被畫出來，不能只留
pass/fail。** 這是三份 review 各自獨立收斂到的同一個結論——所有 graded
practice 步驟背後都是真的組譯、真的跑在 WASM emulator 上，暫存器和記憶體
的真實數值都算好了，但目前大多數關卡完全沒有把這些數值顯示給學習者看，
只給「答對/再試一次」的二元回饋。學習者被要求在腦中模擬看不見的初始狀態
和看不見的執行結果。

**建議做一個可重用的「執行狀態視覺化」元件**，涵蓋：
- 暫存器前後數值（before/after）
- 定址的記憶體格子（address + byte/word 內容），標出目前操作的目標格
- 指令逐步追蹤（code trace）：目前執行到哪一行、跳轉去哪裡

這個元件應該貫穿 L0（指令介紹）、L1（calling convention 練習）、L2（記憶體
定址、syscall 參數）共用，而不是三套各自半吊子的解法（`RegisterBank` 有時
接、有時沒接；`StackDiagram` 只服務 stack overflow 那幾關；程式碼追蹤完全
沒有）。

**`RegisterBank` 只顯示這一步真正用到的暫存器，不要放長期空白的
「誘餌格」。** 目前 L1-2/L1-4 有些暫存器格永遠是空的，只是為了跟選項對
齊而存在，反而增加視覺搜尋負擔卻沒有幫助追蹤狀態。

**多子關卡的視覺元素要能分辨「這是真的東西」還是「這是簡化過的替代
物」。** L2-5c 用合成的 harness 取代敘事中提到的真實 vulnerable binary，
UI 上完全沒有區分，容易造成學習者以為自己操作的就是前面敘述的那個目標。

**題目本身要能被 UI 上顯示的資訊回答，不能考「repo 裡的冷知識」，選項文字
也不能對實際行為說謊。**（2026-08-21 追加，來自 L2-1 的實際案例，確認是
平台性的通病，不是單一關卡的個案）

L2-1 第一個 syscall 練習要學習者從 `0x10000`／`0x20000`／`0x30000` 三個
十六進位選項猜字串的位址，畫面上沒有任何線索能推出正確答案——這是第一層
問題（單純測背誦）。但實際檢查後發現第二層、更嚴重的問題：「正確答案」
顯示的 `0x10000` **根本不是** `msg` 這個字串真正的執行期位址（那其實是
`.text` 段起始位址 `BASE_ADDRESS`，`msg` 實際上被排在所有指令後面的
`.data` 段，位址完全是另一個數字）。而選項底層真正組譯執行的是
`la a1, msg`——一個**完全不需要知道實際數字**的符號式定址指令。也就是說
UI 顯示的選項文字對「實際會執行什麼」說了假話，題目包裝成「猜對一個數字」，
但真正的技能（`la` + label）根本不需要猜數字。

自我檢查這個模式時，要分開檢查兩件事：
1. **可推導性**：這一題的正確答案，學習者能不能單靠畫面上已經顯示的資訊
   推導出來？如果需要暫存器/記憶體視覺化才能推導，畫面上有沒有真的畫出來？
2. **誠實性**：選項顯示的文字（不管是文字敘述還是數字），是不是真的對應
   底層會執行的那段 asm？絕對不能出現「UI 顯示 A，實際執行 B」的情況，
   即使 B 剛好能通過判定也一樣——這種不一致玩家肉眼看不出來，但會讓「猜對
   了却不知道為什麼」變成常態，直接違反這個平台「判定永遠是真的」的核心
   原則的精神。

這個模式已知會出現在「要求選一個記憶體位址／某個數值，但畫面上沒有視覺化
依據」的所有題目，不只 L2-1——寫新關卡或審查既有關卡時要主動檢查每一個
`options`/`optionAsm` 配對，確認顯示文字跟底層 asm 行為一致。

**速查表要有分級/分頁意識，不要對每一關都攤開全部內容。** 目前無論在哪
個關卡打開速查表，看到的都是同一份完整表格，包含尚未教過的 syscall、
暫存器、指令。對正卡關的學習者來說，這反而增加要在一堆未學內容裡找到
相關資訊的負擔。速查表應該知道目前在哪一關，預設只展開已教過的內容，未來
主題收在可展開的「後面會教」區塊。

## 使用方式

寫新關卡或修改既有關卡時，對照以上三節自我檢查：
1. 步數是否落在 5-10？有沒有先示範再考？
2. 有沒有把規則講白，而不是讓學習者自己歸納？有沒有提前洩漏還沒教的詞？
3. 這一步的正確答案，學習者能不能單靠畫面上顯示的資訊推導出來？如果需要
   看暫存器/記憶體才能推導，畫面上有沒有真的畫出來？

三份完整的逐關卡 punch list（含建議的分步順序、新舊 widget 分類）在
`cogload-review-L0.md` / `-L1.md` / `-L2.md`，本文件只整理跨分支共通的
原則。
